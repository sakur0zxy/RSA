# Phase 8.1 Visual Evidence Extraction - Discussion WIP

**状态:** 已完成，已整理进 `08.1-CONTEXT.md` 和 `08.1-DISCUSSION-LOG.md`  
**创建时间:** 2026-05-18  
**用途:** 临时记录 Phase 8.1 讨论结果；每完成一个小点立即记录，最后整理进 `08.1-CONTEXT.md` 和正式 discussion log。

## Phase 边界

Phase 8.1 负责把 Phase 8 的候选 `asset_suggestions`、本地授权 PDF 或已登记本地资产转成可审阅的视觉证据候选。

本阶段可以做：候选裁图/裁表、caption 提取、基础 OCR、page/region/source trace、置信度和中文不确定性说明。

本阶段不做：曲线数据自动还原、高级表格结构理解、图表驱动的正式学术结论、paper quality/relevance/read priority 评分、formal records 写入。

## 已继承决策

- 用户可见内容中文优先；字段名、YAML key、CLI flag、状态枚举和代码标识保持英文稳定，并提供中文解释。
- 所有视觉输出只进入 staging/review，不直接进入 formal records。
- 真实 PDF、裁图、OCR 中间结果和图片文件 local-only，不进入 git。
- 可审计 manifest / suggestion YAML 可以进入 git，但不得包含大段版权文本、密钥、cookie、账号凭据或未授权内容。
- `formal write gate` 不得被 Phase 8.1 绕过。

## 待讨论灰区

1. 默认输入范围：只处理 Phase 8 `asset_suggestions`，还是自动扫描全文 PDF 页面。
2. 输出结构：视觉候选 manifest/schema 如何组织，是否复用 `assets/P###/manifest.yaml`。
3. 提取深度：v1 做到 crop/caption/OCR 的哪一层，哪些直接 deferred。
4. 置信度与降级：低置信度、扫描页、图表边界不清时如何标记 `partial` / `blocked`。
5. CLI 工作流：命令组命名、默认自动程度、人工监管入口。

## 已完成讨论点

### 1. 默认输入范围

**决策:** 选 1，默认采用 `asset_suggestions` + 已授权 PDF 自动扫描。

**中文说明:** Phase 8.1 默认先处理 Phase 8 阅读草稿中给出的 `asset_suggestions`，再对已授权 PDF 做自动视觉扫描，发现候选图、表、caption 和页面区域。这样保持系统“默认自动运行、用户主要监管”的产品方向。

**执行边界:**
- 缺少授权 PDF 或可用本地全文时，不生成伪视觉证据；写入 `blocked` 或 `partial` 状态。
- 自动扫描只生成视觉证据候选，不直接生成正式学术结论。
- `asset_suggestions` 优先级高于全文扫描结果；全文扫描用于补漏。
- 默认不无脑截取论文中所有图片和表格；只保存进入候选清单的视觉证据，避免资产目录膨胀和 review queue 噪声过高。
- 预留扩展模式：`--all-detected` 截取所有检测到的 figure/table，`--pages 3,5-7` 只处理指定页面，`--asset-suggestions-only` 只处理 Phase 8 建议项。

### 2. 输出结构

**决策:** 选 1，采用“双层结构”：资产清单 + 视觉证据候选清单。

**中文说明:** Phase 8.1 同时维护两个层次：
- `assets/P###/manifest.yaml`：记录本地资产文件，例如 PDF、裁图、OCR 结果、截图路径、生成时间、来源。
- `visual_evidence_candidates.yaml`：记录可审阅的视觉证据候选，例如 figure/table 编号、page、region、caption、OCR 摘要、confidence、中文解释和相关文档链接。

**原因:** 文件资产和证据判断必须分开。资产清单回答“文件在哪里、从哪里来”，视觉证据候选回答“这个图表为什么可能有用、证据状态如何”。这样后续 Phase 9 scoring、review workspace 和 formal gate 都能复用。

**字段原则:**
- 字段名保持英文稳定，例如 `candidate_id`、`paper_id`、`asset_id`、`visual_type`、`page`、`region_bbox`、`confidence`、`status`。
- 用户可见解释使用中文字段，例如 `caption_zh`、`ocr_summary_zh`、`evidence_note_zh`。
- 候选记录必须包含 `source_links`，链接到 reading draft、asset manifest、原始 PDF 或本地资产记录，方便用户回看来源。

### 3. 提取深度与扩展接口

**决策:** 当前 Phase 8.1 实现基础视觉证据提取，同时预留 `advanced_analysis` 扩展接口；高级曲线、表格和多模态分析暂不实现。

**当前实现范围:**
- 自动定位候选 `figure` / `table` / `caption` / `equation` / `text` / `unknown` 视觉区域。
- 保存本地裁图或裁表资产，并写入 `assets/P###/manifest.yaml`。
- 提取 caption 候选、基础 OCR 文本摘要、page、region_bbox、source_rects、source_links。
- 输出中文 `evidence_note_zh` 和不确定性说明。

**明确延后范围:**
- 曲线数据自动还原。
- 高级表格结构理解。
- 图中数值自动抽取。
- 多模态模型解释图表。
- 图表证据驱动的自动 scientific claim draft。

**预留接口:** 在候选 schema 中保留 `advanced_analysis`，默认记录 `not_run` 和中文说明，后续高级模块可以把 `not_run` 更新为 `success` / `partial` / `blocked` 并链接结果文件。

示例：

```yaml
advanced_analysis:
  curve_extraction:
    status: not_run
    result_file: null
    note_zh: "当前版本未执行曲线数据还原。"
  table_structure:
    status: not_run
    result_file: null
    note_zh: "当前版本未执行高级表格结构解析。"
  multimodal_interpretation:
    status: not_run
    result_file: null
    note_zh: "当前版本未执行多模态图表解释。"
```

### 4. EasyPaper 借鉴边界

**决策:** 采纳 EasyPaper 的坐标、状态、阅读器和便携知识对象思想，但不照搬其 Web App 架构，也不把轻量 LLM findings 当作 RSA formal records。

**准确定位:** EasyPaper 提供的是“PDF 坐标定位 + 可视化审阅 + 便携知识对象 + Agent 接口”的产品闭环参考。对 RSA 而言，它更适合作为证据定位雏形，而不是完整科研 evidence chain。

**可吸收设计点:**
- Phase 8.1 增加 `sentence_id`、`region_id`、`visual_type`、`page`、`region_bbox`、`source_rects`、`source_text`、`failed_matches`、`evidence_level`、`status`。
- Phase 8.1 候选状态支持 `detected`、`cropped`、`ocr_success`、`ocr_partial`、`needs_review`、`blocked`、`not_run`。
- Phase 9 scoring 只引用 `evidence_candidate_id`，不直接把未确认图像/OCR 结论写入 formal records。
- Phase 10 orchestrator 每个步骤输出 `task_id`、`status`、`progress`、`message_zh`、`error_zh`、`repair_hint_zh`、`artifacts`。
- Phase 12 review workspace 优先实现可点击回源的 PDF/截图证据审阅和 reading draft 对照，暂缓复杂知识图谱和自动 claim draft。

**收紧说明:**
- “PDF 坐标级证据链”在 RSA 文档中应写成“坐标级证据定位雏形”；完整 evidence chain 仍需 RSA 自己维护 claim -> source -> page/region -> confidence/status -> human review。
- EasyPaper 的 Figure/Table 保护区和文本块/坐标提取思路值得借鉴；caption 与 figure/table 的绑定逻辑由 RSA 自己实现。
- EasyPaper 的处理状态适合 Phase 10 借鉴，但 RSA 还必须保留 `blocked` / `partial` / `needs_review` / `skipped` / `not_run` 和中文失败原因、修复建议。
- 便携知识 JSON 只能作为中间产物和机器状态，不能替代 `paper_index.md`、`literature_map.md`、`research_tables.md`、reading notes 等 formal records。

### 5. LLM 辅助图片分析的阶段归属

**决策:** 不新开完整独立 phase；采用“两层放置”：
- Phase 8.1 负责准备 LLM 图片分析所需的上下文包和接口。
- Phase 9 负责真正融合正文、caption、OCR、视觉候选和 LLM 解释，进入 evidence signals 与 AI scoring。

**中文说明:** 用户希望论文图片分析引入 LLM，并结合上下文，尤其结合原论文对图片的描述来分析。这个方向值得做，但如果把“LLM 图像理解 + 上下文融合 + 评分判断”全部塞进 Phase 8.1，会让 Phase 8.1 从“视觉证据候选提取”膨胀成“多模态科研解释”。因此 Phase 8.1 只准备材料，不做最终判断。

**Phase 8.1 应做:**
- 为每个视觉候选生成 `visual_context_packet`。
- 收集裁图、caption、附近正文、figure/table 引用句、OCR 文本、page/region/source trace。
- 预留 `llm_visual_analysis` 字段，默认 `not_run`，可记录模型名、prompt version、输入证据范围、中文解释和不确定性。
- 输出仍然是 candidate，不是正式结论。

**Phase 9 应做:**
- 调用或消费 LLM 图片分析结果。
- 把图像解释与正文 evidence、reading draft、topic profile 合并成 `evidence_signals`。
- 只把结果用于 relevance / quality / read priority 的辅助评分和 review queue。
- 不绕过 formal write gate，不把未确认图像解释写入 formal records。

**边界:** 若后续要做曲线数据还原、高级表格结构理解、图像问答、多模态 claim draft，可作为 deferred advanced figure intelligence 或 Phase 13 之后的独立增强；当前不纳入 Phase 8.1 主实现。

### 6. 置信度与降级策略

**决策:** 选 1，采用保守降级策略：尽量保留可审阅候选，但明确标记风险和修复建议。

**中文说明:** Phase 8.1 不应因为低置信度就直接丢弃所有视觉线索，也不应把不稳定结果伪装成可靠证据。默认做法是保留候选、降低状态等级，并让用户或后续 review workspace 能看到问题在哪里。

**状态规则:**
- 能定位图表但边界不稳：`status: needs_review`。
- 裁图成功但 OCR 不完整：`status: ocr_partial`。
- 页面可读但 caption 绑定不确定：`confidence: low`，并写 `warning_zh`。
- 扫描页无法可靠提取文本但可形成视觉候选：`evidence_level: visual_only`。
- 完全无法定位、PDF 不可读、缺少授权全文或源文件损坏：`status: blocked`。
- 未执行的高级能力：`status: not_run`，并写明当前版本未执行。

**必填中文说明:**
- `warning_zh`：说明不确定性，例如“图表边界可能不完整”或“caption 与裁图绑定置信度较低”。
- `repair_hint_zh`：说明可恢复动作，例如“可使用 --pages 指定页面重试”或“可使用 --all-detected 生成完整候选后人工筛选”。
- `evidence_note_zh`：说明该候选为什么可能有用，但不得写成正式学术结论。

### 7. CLI 工作流与默认自动程度

**决策:** 选 1，采用单主命令 + 明确扩展参数。

**主命令:**

```bash
rsa visual extract P001
```

**默认行为:** 自动读取 source ledger / reading draft，处理 `asset_suggestions`，扫描授权 PDF，生成候选截图、asset manifest 更新和 `visual_evidence_candidates.yaml`。

**扩展参数:**

```bash
rsa visual extract P001 --all-detected
rsa visual extract P001 --pages 3,5-7
rsa visual extract P001 --asset-suggestions-only
rsa visual validate P001
rsa visual status P001
```

**中文说明:** Phase 8.1 默认应足够自动，符合 RSA “用户主要监管”的方向；同时保留明确重试和人工控制入口。Phase 10 orchestrator 后续可以直接调用 `rsa visual extract P001` 作为自动链路中的一个步骤。

**边界:**
- 不把视觉提取并入 `rsa note draft`，保持 Phase 8 和 Phase 8.1 边界清晰。
- 不拆成必须手动串联的 `detect/crop/ocr/packet` 多命令，避免降低默认自动化程度。
- `validate` 和 `status` 必须只读。
