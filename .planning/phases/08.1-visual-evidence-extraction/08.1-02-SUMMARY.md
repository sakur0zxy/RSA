# Phase 08.1-02 Summary: PDF Visual Extraction Engine And Context Packets

## Completed

- 将 `PyMuPDF>=1.24` 加入基础依赖，因为视觉候选提取属于 v2 核心闭环。
- `fitz` 采用 lazy import；缺少 PyMuPDF 时返回中文 `VisualError`，不产生伪候选。
- 实现 `extract_visual_evidence(config, paper_id, *, all_detected=False, pages=None, asset_suggestions_only=False)`。
- 支持三种扩展模式：
  - `asset_suggestions_only=True`：只把 Phase 8 `asset_suggestions` 转成候选。
  - `pages={...}`：只处理指定 PDF 页码。
  - `all_detected=True`：显式裁取所有检测到的图表/表格样候选。
- 使用 PyMuPDF `page.get_text("dict")` 读取 image/text blocks，检测 image block、caption-like text block、页面/区域坐标。
- 成功候选会写入：
  - PNG crop: `01_literature/assets/P###/crops/V###.png`
  - asset manifest entry: `generated_by: rsa visual extract`
  - local context packet: `01_literature/assets/P###/visual_context_packets/V###.yaml`
  - review candidate: `visual_evidence_candidates.yaml`

## Safety Boundary

- 默认模式不会盲目裁取整篇论文所有图片；全量模式必须显式使用 `--all-detected`。
- 视觉候选不会调用 formal 写入路径。
- 曲线数值还原、高级表格结构理解、LLM 图像解释保持 `not_run`。
- 视觉-only 候选必须带中文 warning，避免被误读为已验证证据。

## Verification

- Synthetic PDF tests now run after installing PyMuPDF.
- Tests cover asset-suggestions-only、all-detected、page restriction、crop file、manifest integration、context packet and validation.
