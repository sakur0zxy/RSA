## Must Haves

<must_haves>
<truth id="D-01">D-01: Phase 10 models one paper as the sequential chain `acquisition -> reading_draft -> visual_extraction -> scoring -> review_packet`.</truth>
<truth id="D-02">D-02: The schema must be reusable by Phase 11, but this plan must not implement campaign queues, campaign ranking, stage concurrency or batch aggregation.</truth>
<truth id="D-03">D-03: The schema must carry `partial_reason_zh`, `evidence_level`, affected step and supervision guidance so partial results can continue safely.</truth>
<truth id="D-04">D-04: The schema must carry blocked run and step states with Chinese failure reasons and repair hints for fail-closed stops.</truth>
<truth id="D-05">D-05: The schema must carry `needs_review` reasons and evidence links so the final review packet can highlight supervision points.</truth>
<truth id="D-06">D-06: The schema must state that workflow runs cannot perform formal writes or bypass `rsa formal ...` human confirmation gates.</truth>
<truth id="D-07">D-07: The default visual step in the schema is the conservative `rsa visual extract P###` step, not true LLM image interpretation.</truth>
<truth id="D-08">D-08: Future advanced figure intelligence interfaces must be represented as `not_run` placeholders for `llm_visual_analysis`, `advanced_analysis.curve_extraction`, `advanced_analysis.table_structure` and `advanced_analysis.multimodal_interpretation`.</truth>
<truth id="D-09">D-09: The main workflow target is a single formal `paper_id` such as `P001`.</truth>
<truth id="D-10">D-10: Campaign context fields are optional metadata: `campaign_id` and `campaign_item_id`.</truth>
<truth id="D-11">D-11: The schema must not imply that `rsa workflow run C001` is valid batch scheduling.</truth>
<truth id="D-12">D-12: Campaign context may later carry topic profile, priority question, objective, import source and dedup/link data into scoring and reports.</truth>
<truth id="D-13">D-13: Run state must preserve `campaign_id` and `campaign_item_id` for Phase 11 aggregation.</truth>
<truth id="D-14">D-14: Workflow state is stored per paper under `01_literature/workflows/P001/RUN-001.yaml` style paths.</truth>
<truth id="D-15">D-15: Each run file must contain a full step ledger with `step_id`, `command`, `status`, timestamps, input summary, artifact links, `error_zh`, `repair_hint_zh`, `retryable` and `needs_user_action`.</truth>
<truth id="D-16">D-16: Run YAML must store concise Chinese summaries and artifact paths, not full stdout/stderr, secrets, credentials or copyrighted content.</truth>
<truth id="D-17">D-17: The schema must support resume from the last unfinished, failed or retryable step.</truth>
<truth id="D-18">D-18: Completed steps are reusable only after lightweight artifact validation, not because YAML says `completed`.</truth>
<truth id="D-19">D-19: Artifact validation failure must force rerun from that step or stop to repair.</truth>
<truth id="D-20">D-20: The schema must support explicit `from_step` overrides and Chinese warnings about reuse, overwrite and regeneration.</truth>
<truth id="D-26">D-26: Workflow steps may be skipped by local config or command flags, with command flags taking priority.</truth>
<truth id="D-27">D-27: Skipped steps must be recorded as `status: skipped` with `skipped_reason_zh`, never as successful completion.</truth>
<truth id="D-28">D-28: Phase 10 schema must preserve one-paper sequential execution while staying ready for Phase 11 campaign-level controlled parallelism.</truth>
<truth id="D-29">D-29: Run state must preserve batch-ready fields including `run_id`, `paper_id`, `campaign_id`, `campaign_item_id`, `step_id`, `step_status`, `artifacts`, `blocked_reason_zh`, `partial_reason_zh` and `retry_policy`.</truth>
<truth id="D-30">D-30: Phase 11 owns campaign worker queues, per-stage concurrency, campaign sorting/filtering and batch exception aggregation.</truth>
</must_haves>

<threat_model>
- **Threat:** Later agents treat run YAML as a global queue or campaign scheduler. **Mitigation:** per-paper paths, single-paper step order and explicit Phase 11 ownership fields.
- **Threat:** A skipped or partial step looks like completion. **Mitigation:** explicit `skipped`, `partial`, `needs_review` statuses and Chinese reason fields.
- **Threat:** Run files collect secrets, stdout dumps or copyrighted text. **Mitigation:** schema stores concise summaries and artifact links only.
- **Threat:** Advanced figure intelligence appears implemented before it is safe. **Mitigation:** all advanced interfaces default to `not_run` with Chinese explanation.
</threat_model>
