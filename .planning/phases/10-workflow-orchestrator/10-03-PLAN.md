# Phase 10-03 Plan: Workflow CLI Controls Reports And Docs

## Objective

<objective>
Expose the Phase 10 workflow engine through Chinese-first CLI commands, reports, documentation and final GSD state updates. This plan gives users the monitor/control surface for automated single-paper workflows while preserving formal-write gates and Phase 11 campaign boundaries.

## Must Haves

<must_haves>
<truth id="D-01">D-01: CLI `workflow run` must execute the single-paper sequential chain `acquisition -> reading_draft -> visual_extraction -> scoring -> review_packet`.</truth>
<truth id="D-02">D-02: CLI workflow commands must not implement campaign worker queues, stage-level concurrency, campaign ranking or batch exception aggregation.</truth>
<truth id="D-03">D-03: CLI output and reports must explain `partial` in Chinese and continue to review packet when upstream artifacts remain usable.</truth>
<truth id="D-04">D-04: CLI output and reports must explain `blocked` in Chinese and avoid presenting blocked runs as completed review packets.</truth>
<truth id="D-05">D-05: CLI output and reports must explain `needs_review` in Chinese and link the evidence and recommended action.</truth>
<truth id="D-06">D-06: CLI commands and docs must state that formal write requests stop before formal records and require explicit `rsa formal ...` gates plus human confirmation.</truth>
<truth id="D-09">D-09: The main user entry point is `rsa workflow run P001`.</truth>
<truth id="D-10">D-10: `--campaign-id C001` and `--campaign-item-id CI001` are optional context flags.</truth>
<truth id="D-11">D-11: CLI must not accept campaign id as the main `workflow run` target.</truth>
<truth id="D-12">D-12: When campaign context exists, reports should include campaign objective, topic profile, priority question and dedup/linking context when available.</truth>
<truth id="D-13">D-13: CLI-generated run state must preserve `campaign_id` and `campaign_item_id` for Phase 11 aggregation.</truth>
<truth id="D-14">D-14: CLI commands must read/write per-paper run state under `01_literature/workflows/P001/RUN-001.yaml` style paths.</truth>
<truth id="D-15">D-15: Status and report output must expose the step ledger fields users need: command, status, artifacts, Chinese error/reason, retryability and next action.</truth>
<truth id="D-16">D-16: CLI reports must avoid full stdout/stderr, secrets, credentials and copyrighted content dumps.</truth>
<truth id="D-17">D-17: `rsa workflow resume P###` resumes from the last unfinished, failed or retryable step by default.</truth>
<truth id="D-18">D-18: `status` and `resume` must not trust `completed` without lightweight artifact validation.</truth>
<truth id="D-19">D-19: Artifact validation failures must be shown as rerun/repair guidance in Chinese.</truth>
<truth id="D-20">D-20: `--from-step <step_id>` must produce Chinese warnings about reused, overwritten or regenerated artifacts.</truth>
<truth id="D-21">D-21: CLI must expose `run`, `resume`, `status`, `report`, `stop` and `rerun --from-step` controls.</truth>
<truth id="D-22">D-22: `stop` must mark the workflow user-stopped or user-paused and prevent later automatic resume without explicit action.</truth>
<truth id="D-23">D-23: `rerun` must explicitly say which artifacts are reused, overwritten or regenerated.</truth>
<truth id="D-24">D-24: `resume --from-step` is recovery; `rerun --from-step` is user-requested recomputation.</truth>
<truth id="D-25">D-25: Users must be able to monitor important points through `status` and `report`, and adjust flow through `stop`, `rerun`, `resume`, local config and flags.</truth>
<truth id="D-26">D-26: CLI skip flags must override local skip defaults.</truth>
<truth id="D-27">D-27: Skipped steps must appear as `status: skipped` with `skipped_reason_zh` in status and report output.</truth>
<truth id="D-28">D-28: Docs must explain the layered parallelism split: Phase 10 single-paper sequential workflow, Phase 11 campaign-level controlled parallelism.</truth>
<truth id="D-29">D-29: CLI output and docs must preserve batch-ready fields including `run_id`, `paper_id`, `campaign_id`, `campaign_item_id`, `step_id`, `step_status`, `artifacts`, `blocked_reason_zh`, `partial_reason_zh` and `retry_policy`.</truth>
<truth id="D-30">D-30: Docs must state that campaign worker queues, per-stage concurrency limits, sorting/filtering and batch exception aggregation belong to Phase 11.</truth>
</must_haves>

<threat_model>
- **Threat:** CLI makes Phase 10 look like a campaign scheduler. **Mitigation:** reject `C###` targets, document campaign context as metadata only, and point batch execution to Phase 11.
- **Threat:** Users cannot understand what happened in automation. **Mitigation:** Chinese-first status/report output with step table, reasons, artifacts and next action.
- **Threat:** Resume/rerun controls overwrite user work silently. **Mitigation:** explicit warnings, downstream pending/regeneration markers and artifact validation.
- **Threat:** Workflow bypasses formal gate. **Mitigation:** report-only formal requests and documentation/tests for formal-write boundary.
</threat_model>
