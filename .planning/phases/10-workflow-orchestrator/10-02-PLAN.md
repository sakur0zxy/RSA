# Phase 10-02 Plan: Single Paper Workflow Engine

## Objective

<objective>
Implement the reusable single-paper workflow engine that chains existing acquisition, reading draft, visual extraction, scoring and review packet functionality. The engine should automatically advance ordinary steps, stop fail-closed on `blocked`, continue with explicit audit information on `partial`, continue to review packet on `needs_review`, and always stop before formal writes.
</objective>

## Must Haves

<must_haves>
<truth id="D-01">D-01: The engine executes one paper in this order: `acquisition -> reading_draft -> visual_extraction -> scoring -> review_packet`.</truth>
<truth id="D-02">D-02: The engine exposes a reusable primitive for Phase 11 but must not implement many-paper traversal, worker queues, ranking or batch exception aggregation.</truth>
<truth id="D-03">D-03: `partial` continues when source, schema and core upstream artifacts remain usable, while recording `partial_reason_zh`, `evidence_level`, affected step and supervision guidance.</truth>
<truth id="D-04">D-04: `blocked` stops the current paper immediately, records Chinese error and repair hint, and does not generate a normal completed review packet.</truth>
<truth id="D-05">D-05: `needs_review` continues to review packet, then stops for supervision with reason, evidence links and recommended action.</truth>
<truth id="D-06">D-06: Formal write requests must be surfaced only as review items; the workflow engine may not call formal apply commands or set human confirmation.</truth>
<truth id="D-07">D-07: The visual step defaults to the existing conservative `extract_visual_evidence` path, not true LLM image interpretation.</truth>
<truth id="D-08">D-08: The engine preserves artifact links/status for future `llm_visual_analysis` and advanced analysis fields as `not_run` unless existing Phase 8.1 artifacts say otherwise.</truth>
<truth id="D-12">D-12: Optional campaign context may inform scoring, review packet text and run state when provided.</truth>
<truth id="D-13">D-13: `campaign_id` and `campaign_item_id` must be preserved in run state for Phase 11 aggregation.</truth>
<truth id="D-17">D-17: Resume defaults to the last unfinished, failed or retryable step.</truth>
<truth id="D-18">D-18: Reused completed steps must pass lightweight artifact validation: file exists, schema is valid, ids match and status is safe.</truth>
<truth id="D-19">D-19: If artifact validation fails, the engine must rerun from that step or stop with a repair state instead of trusting stale YAML.</truth>
<truth id="D-20">D-20: `from_step` overrides must warn in Chinese about reused, overwritten or regenerated artifacts.</truth>
<truth id="D-26">D-26: Local config skips and command-level skip overrides must be respected, with command flags having higher priority.</truth>
<truth id="D-27">D-27: Skipped steps are recorded as `status: skipped` with `skipped_reason_zh` and cannot satisfy downstream artifact validation as normal completion.</truth>
<truth id="D-28">D-28: Single-paper execution remains sequential even though Phase 11 may later run many papers with controlled pipeline parallelism.</truth>
<truth id="D-29">D-29: Engine updates must preserve batch-ready fields including `run_id`, `paper_id`, `campaign_id`, `campaign_item_id`, `step_id`, `step_status`, `artifacts`, `blocked_reason_zh`, `partial_reason_zh` and `retry_policy`.</truth>
<truth id="D-30">D-30: Campaign worker queues, per-stage concurrency limits, campaign sorting/filtering and batch exception aggregation remain outside this engine.</truth>
</must_haves>

## Tasks

<tasks>
<task id="10-02-T1" type="auto">
<files>
- `src/rsa_cli/workflow.py`
- `tests/test_workflow.py`
</files>
<action>
Add workflow engine entry points:
- `run_workflow(config, paper_id, campaign_id=None, campaign_item_id=None, skip_steps=None, from_step=None, run_id=None)`;
- `resume_workflow(config, paper_id, from_step=None)`;
- `rerun_workflow(config, paper_id, from_step)`;
- `stop_workflow(config, paper_id, reason_zh=None)`;
- `workflow_status(config, paper_id)`.

These functions update run YAML after each step, keep status transitions explicit, and never hide failures behind a successful exit status in the run file.
</action>
<acceptance_criteria>
- A fresh run creates `RUN-001.yaml` and advances through the canonical step list.
- Resume chooses the last unfinished/failed/retryable step unless `from_step` is provided.
- Rerun from a step marks downstream steps pending/regenerated and records Chinese warnings.
- Stop marks the run `stopped` and prevents automatic resume without explicit user action.
</acceptance_criteria>
</task>

<task id="10-02-T2" type="auto">
<files>
- `src/rsa_cli/workflow.py`
- `src/rsa_cli/acquisition.py`

- `src/rsa_cli/visual.py`

<action>
Implement step wrappers that reuse existing module functions rather than duplicating business logic:
- acquisition step: reuse `find_sources`, `discover_source_candidates`, `download_best_candidate`, `candidate_status` and source-ledger artifacts as appropriate.
- reading draft step: reuse `draft_reading_note` and its note/review packet/extraction artifacts.
- visual extraction step: reuse `extract_visual_evidence` and `visual_status`.
- scoring step: reuse `score_paper` and `score_status`.
- review packet step: aggregate existing note review packet, visual context packets, scoring review packet and run state into workflow-level review output.

Each wrapper must convert module-specific outcomes into workflow statuses and Chinese status summaries without swallowing the original artifact path.
</action>
<acceptance_criteria>
- Existing acquisition, reading, visual and scoring tests still pass.
- Workflow tests can exercise success, partial, blocked, needs_review and skipped transitions with small fixtures.
- The engine does not call CLI subprocesses for internal steps when direct Python helpers are available.
</acceptance_criteria>
</task>

<task id="10-02-T3" type="auto">
<files>
- `src/rsa_cli/workflow.py`
- `tests/test_workflow.py`
</files>
<action>
Add lightweight artifact validation before reusing completed steps. Validation should check:
- expected artifact file exists;
- artifact schema validator passes when available;
- `paper_id`, `campaign_id`, `campaign_item_id` or source identifiers match when present;
- status is safe to reuse;
- skipped steps are not treated as completed.

If validation fails, mark the affected step as `failed` or `blocked` with Chinese repair guidance and either rerun from that step or require explicit recovery.
</action>
<acceptance_criteria>
- Deleting an artifact after a completed run prevents silent reuse.
- A mismatched `paper_id` in an artifact prevents silent reuse.
- A skipped step does not satisfy downstream validation as completion.
- The run file records `repair_hint_zh` for validation failures.
</acceptance_criteria>
</task>

<task id="10-02-T4" type="auto">
<files>
- `src/rsa_cli/workflow.py`
- `tests/test_workflow.py`
</files>
<action>
Implement workflow-level review packet generation for successful, partial and needs-review runs. The report should link:
- formal metadata;
- source candidate/source ledger files;
- reading note draft and reading review packet;
- visual candidate YAML and visual context packets;
- scoring YAML and scoring review packet;
- workflow run YAML;
- future advanced visual interfaces with current `not_run` status.

Blocked runs should write a blocked status/report instead of a normal completed review packet.
</action>
<acceptance_criteria>
- Completed runs generate a Markdown workflow report with Chinese section text and English artifact keys.
- Partial and needs-review reports highlight supervision items.
- Blocked runs produce a fail-closed report that does not look complete.
- No workflow report writes or modifies formal records.
</acceptance_criteria>
</task>
</tasks>

<threat_model>
- **Threat:** The engine duplicates step logic and drifts from existing commands. **Mitigation:** call existing Python helpers and keep wrappers thin.
- **Threat:** The engine over-automates formal writes. **Mitigation:** formal requests are report links only; no formal apply calls.
- **Threat:** Stale artifacts make resume unsafe. **Mitigation:** artifact validation before reuse and explicit rerun/repair states.
- **Threat:** Partial visual evidence contaminates scoring/reporting. **Mitigation:** carry `evidence_level`, degraded reasons and `needs_review` guidance into scoring and workflow report.
</threat_model>
