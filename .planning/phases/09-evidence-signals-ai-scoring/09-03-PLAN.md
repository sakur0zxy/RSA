## Must Haves

<must_haves>
<truth id="D-01">D-01: Campaign scoring must reuse the single-paper scoring core.</truth>
<truth id="D-02">D-02: `rsa score P001` is the smallest verifiable CLI unit.</truth>
<truth id="D-03">D-03: Campaign command may iterate and summarize but must not implement Phase 11 review management.</truth>
<truth id="D-04">D-04: CLI output must point to `01_literature/scores/P###_scoring.yaml` for single-paper YAML.</truth>
<truth id="D-05">D-05: CLI output must point to `01_literature/campaigns/C###_scoring_summary.yaml` for campaign summaries.</truth>
<truth id="D-06">D-06: CLI text must keep `agent_review_score_10` clearly separate from Phase 9 relevance/quality/priority scores.</truth>
<truth id="D-07">D-07: CLI and README must state that score YAML/review packets are staging/review outputs, not formal records.</truth>
<truth id="D-26">D-26: CLI must expose or report only allowed AI review decisions: `recommend_pass`, `recommend_defer`, `needs_review`, `blocked`.</truth>
<truth id="D-27">D-27: Campaign summary may rank/sort staging guidance but not formal approval.</truth>
<truth id="D-28">D-28: Chinese docs must explain that users supervise risky items rather than confirming every AI initial judgment.</truth>
<truth id="D-29">D-29: CLI review command must support later human correction.</truth>
<truth id="D-30">D-30: CLI review command must preserve traceable review history.</truth>
<truth id="D-31">D-31: No Phase 9 CLI command may write formal records.</truth>
<truth id="D-32">D-32: CLI command group must include `rsa score P001`, `rsa score validate P001`, `rsa score status P001`, `rsa score campaign C001`, and `rsa score review P001 --final-decision approved|rejected|deferred --reviewer zxy --reason "中文原因"`.</truth>
<truth id="D-33">D-33: Required outputs are single-paper scoring YAML, single-paper review packet and campaign scoring summary YAML.</truth>
<truth id="D-34">D-34: `validate` and `status` commands must be read-only.</truth>
<truth id="D-35">D-35: `review` may update human supervision/correction fields but must not write formal records.</truth>
<truth id="D-36">D-36: All user-visible help, output, errors, review packets and repair hints must be Chinese-first.</truth>
</must_haves>

<action>
Add `score` command group to `cli.py`:
- `rsa score P001`;
- `rsa score validate P001`;
- `rsa score status P001`;
- `rsa score campaign C001`;
- `rsa score review P001 --final-decision approved|rejected|deferred --reviewer zxy --reason "中文原因"`.

Follow existing argparse style. Help text, success text and expected errors must be Chinese-first. The positional `rsa score P001` command should be implemented as the single-paper default action when the first score subcommand is not one of `validate`, `status`, `campaign`, or `review`.
</action>
<acceptance_criteria>
- `python -m rsa_cli.cli --help` shows Chinese help for `score`.
- `rsa score validate P001` and `rsa score status P001` are read-only.
- `rsa score review` requires reviewer and Chinese reason.
- Expected `ScoringError` messages are printed in Chinese and return nonzero.
</acceptance_criteria>
</task>

</acceptance_criteria>
