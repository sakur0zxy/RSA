## Objective

<objective>
Implement the single-paper Phase 9 scoring engine that consumes formal metadata, Phase 8 reading notes and Phase 8.1 visual evidence candidates, generates structured evidence signals, writes scoring YAML, writes a Chinese review packet, and supports traceable human correction without formal writes.

## Must Haves

<must_haves>
<truth id="D-08">D-08: Phase 9 must generate structured `evidence_signals` before scoring.</truth>
<truth id="D-09">D-09: Text signals must include `problem_signal`, `method_signal`, `experiment_signal`, `dataset_signal`, `metric_signal`, `finding_signal`, and `limitation_signal`.</truth>
<truth id="D-10">D-10: Visual signals must include `visual_candidate_ids`, `visual_type`, `evidence_level`, `confidence`, and `degraded_reason_zh`.</truth>
<truth id="D-11">D-11: Topic signals must record matches to `topic_profile` and `priority_question` with Chinese explanations.</truth>
<truth id="D-12">D-12: Provenance links must trace to reading note, source chunk, page/region, visual candidate id and related artifact paths.</truth>
<truth id="D-13">D-13: Uncertainty signals must record abstract-only evidence, missing full text, low-confidence visual evidence, OCR partial success and text/visual conflicts.</truth>
<truth id="D-15">D-15: Scoring must produce separate relevance, quality and read-priority scores.</truth>
<truth id="D-16">D-16: Quality scoring must be rubric-backed with method, experiment, comparison, reproducibility and limitation subitems.</truth>
<truth id="D-19">D-19: Phase 8.1 visual evidence candidates may participate as weighted signals.</truth>
<truth id="D-20">D-20: High-confidence visual evidence can strengthen experiment, comparison, result support and reproducibility scoring.</truth>
<truth id="D-21">D-21: Low-confidence visual evidence can only be weak signal, must lower `score_confidence`, and must include `degraded_reason_zh`.</truth>
<truth id="D-22">D-22: Missing visual evidence must not block scoring, but must state evidence-scope limitation in Chinese.</truth>
<truth id="D-23">D-23: Text/visual conflicts must set scoring state to `needs_review`.</truth>
<truth id="D-24">D-24: Unconfirmed OCR or LLM visual interpretations must not enter formal records.</truth>
<truth id="D-25">D-25: AI may make staging judgments automatically, while preserving supervision and traceability.</truth>
<truth id="D-27">D-27: AI may automatically sort/filter/advance review queue state only at the staging/review layer.</truth>
<truth id="D-28">D-28: Users supervise key risky items instead of confirming every initial AI judgment.</truth>
<truth id="D-29">D-29: Later human correction must be supported when a paper is found problematic.</truth>
<truth id="D-30">D-30: Human correction must append traceable history instead of silently overwriting.</truth>
<truth id="D-31">D-31: Scoring/review output must not bypass formal write gates.</truth>
<truth id="D-33">D-33: Single-paper outputs include `P###_scoring.yaml` and `P###_review_packet.md`.</truth>
<truth id="D-34">D-34: Status and validation behaviors must be read-only.</truth>
<truth id="D-35">D-35: Review correction updates supervision fields only and must not write formal records.</truth>
</must_haves>

## Tasks

<tasks>
<task id="09-02-T1" type="auto">
<files>
- `src/rsa_cli/scoring.py`
- `tests/test_scoring.py`
</files>
<action>
Implement `build_evidence_signals(config, paper_id, campaign_item=None)`:
- require valid formal `metadata/P###.yaml`;
- require a readable Phase 8 reading note unless scoring is explicitly blocked;
- read `source_grounded_claims`, `short_quotes`, `uncertain_points_zh`, `asset_suggestions`, topic fields and source links;
- read Phase 8.1 visual candidates if present;
- produce text, visual, topic, provenance and uncertainty signal mappings.

Missing visual candidates must produce a limitation note, not a hard failure. Missing metadata or missing reading note must fail closed with Chinese reason and no fake normal score.
</action>
<acceptance_criteria>
- Missing metadata blocks scoring with a Chinese error mentioning formal metadata.
- Missing reading note blocks normal scoring and writes no successful scoring file.
- Missing visual candidates creates a limitation such as `缺少视觉证据候选` without blocking the paper.
- Low-confidence or partial visual candidates add `degraded_reason_zh`.
</acceptance_criteria>
</task>

<task id="09-02-T2" type="auto">
<files>
- `src/rsa_cli/scoring.py`
- `tests/test_scoring.py`
</files>
<action>
Implement `score_paper(config, paper_id, campaign_item=None, overwrite=False)`:
- build evidence signals;
- compute deterministic 0-10 relevance, quality and read-priority scores from available signals;
- compute quality rubric subitems;
- compute `score_confidence`;
- compute `ai_review_decision`;
- write `P###_scoring.yaml`;
- write `P###_review_packet.md`.

Use deterministic local rules for v1 of Phase 9 implementation so tests do not require an external LLM. Keep the output schema compatible with later LLM-assisted scoring and include `score_version`.
</action>
<acceptance_criteria>
- A paper with grounded claims and valid metadata gets three 0-10 scores.
- A paper with high-confidence visual experiment/result evidence can improve quality and priority within bounded rules.
- A paper with low-confidence visual evidence lowers `score_confidence`.
- A detected text/visual conflict sets `ai_review_decision: needs_review`.
- Review packet uses Chinese headings, explains score meanings, links source artifacts and states that outputs are staging guidance only.
</acceptance_criteria>
</task>

<task id="09-02-T3" type="auto">
<files>
- `src/rsa_cli/scoring.py`
- `tests/test_scoring.py`
</files>
<action>
Implement read-only status and review correction helpers:
- `score_status(config, paper_id)` returns summary counts/fields without writing.
- `validate_scoring_record(config, paper_id)` remains read-only.
- `review_score(config, paper_id, final_decision, reviewer, reason, override_scores=None)` updates `human_review`, appends `review_history`, and rewrites only the scoring YAML/review packet.

Allowed `final_decision` values: `approved`, `rejected`, `deferred`. The helper must clearly state in Chinese that this is review supervision for Phase 9 scoring, not a formal write.
</action>
<acceptance_criteria>
- `score_status` does not change file modification time.
- `validate_scoring_record` does not change file modification time.
- `review_score` appends history with reviewer, timestamp, previous decision, new decision, changed scores and `change_reason_zh`.
- `review_score` never writes metadata, paper index, literature map, agent research notes or formal output files.
</acceptance_criteria>
</task>
</tasks>

<threat_model>
- **Threat:** Deterministic score rules become hidden academic judgment. **Mitigation:** packet labels all scores as AI-assisted staging guidance and stores `scoring_basis` plus limitations.
- **Threat:** Missing evidence is treated as negative proof. **Mitigation:** uncertainty signals distinguish missing evidence from negative findings.
- **Threat:** Human correction history is lost. **Mitigation:** append-only `review_history` and explicit previous/new decision fields.
</threat_model>
