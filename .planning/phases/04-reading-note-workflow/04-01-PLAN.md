# Plan 04-01: Paper Note Template And Authorized-Content Checks

<objective>
Create a deterministic single-paper reading note workflow that only creates notes from existing formal metadata and authorized local source files.
</objective>

<must_haves>
- Implement `rsa note create P### --source-file <path> --authorization provided|local|authorized`.
- Implement `rsa note validate P###` as a read-only schema check.
- Implement `rsa note status P###` as a read-only status summary.
- Missing source files or unavailable authorization must update `pdf_acquisition_report.md` and must not create a reading note.
- Reading notes must distinguish `source_grounded_claims`, `short_quotes`, `agent_summary`, and `human_decision`.
- User-facing output must be Chinese-readable with stable English field names.
</must_haves>

<tasks>
1. Add `ProjectConfig.notes_root` and `ProjectConfig.pdf_acquisition_report_path`.
2. Add `src/rsa_cli/notes.py` with note creation, frontmatter parsing, validation, and blocked status recording.
3. Update root and fallback `paper_note.md` templates with YAML frontmatter and Chinese field explanations.
4. Add CLI `note` subcommands and expected non-traceback error handling.
5. Add unit and CLI tests for authorized creation, missing source behavior, read-only validation, and template localization.
</tasks>

<verification>
- `python -m pytest tests/test_notes.py tests/test_cli.py tests/test_templates.py -q`
- `rsa note validate` must not modify note content.
</verification>
