<objective>
Implement Phase 3 literature map validation, map proposal output, and research gap reports.

Purpose: connect verified formal papers to topic questions, thesis sections, planned outputs, and research roles through a structured `literature_map.md`, then show which topic profile priority questions are covered, weak, or missing without treating generated reports as final academic conclusions.

Output: a map parser/renderer module, updated literature map seed, CLI commands for map validation/proposal and gap generation/validation, and tests for metadata linkage, role/status vocabulary, gap status rules, and read-only versus generated-output boundaries.
</objective>

<scope>
In scope:
- Update `01_literature/literature_map.md` and `templates/map_integration.md` to the D-09 column contract with Chinese field explanations.
- Add map parsing and validation helpers in `src/rsa_cli/map.py` or an equivalently named module.
- Add `rsa map validate` as read-only.
- Add `rsa map propose --round R001_xxx` to generate a map proposal from validated round request data without modifying the formal map.
- Add `rsa gap generate --topic TOPIC_ID` to write a generated report under `01_literature/synthesis/`.
- Add `rsa gap validate --topic TOPIC_ID` as a read-only stale/mismatch check if a generated report exists.
- Reuse metadata validation and topic profile parsing patterns instead of duplicating source-of-truth rules.

Out of scope:
- Do not apply formal map rows to `literature_map.md`; that belongs to 03-03.
- Do not create new `paper_id` values.
- Do not convert candidate titles directly into formal map rows.
- Do not implement reading notes, PDF processing, scholarly API search, Web UI, or thesis prose generation.
</scope>

<threat_model>
- T-03-02-01 Invalid formal references: map rows may point to missing or unverified papers. Mitigate by validating every `paper_id` against formal metadata using existing metadata checks.
- T-03-02-02 Ambiguous map semantics: multiple questions or roles in one cell make gap detection unreliable. Mitigate with one row per paper-question-role relationship and bounded vocabularies.
- T-03-02-03 Generated-output confusion: map proposal or gap report could be mistaken for formal records. Mitigate by writing proposals/reports as generated guidance and documenting that formal map writes require 03-03 guardrails.
- T-03-02-04 Weak coverage misclassification: background-only evidence could appear fully covered. Mitigate with `weak` status and explicit `weak_reason` values.
- T-03-02-05 Validation side effects: a validate command could rewrite formal records. Mitigate by making `validate` commands read-only and testing unchanged file contents.
</threat_model>
