<objective>
Implement Phase 3 round archive completion validation.

Purpose: make every bounded research round inspectable through a concise archive containing `README.md`, `final_round_summary.md`, and only declared optional files, while preserving the rule that automated flows may suggest `ready_for_review` but cannot complete a round without human confirmation fields.

Output: a YAML-frontmatter `final_round_summary.md` template, round archive validation helpers, CLI validation commands, and regression tests for required files, optional manifests, candidate review decisions, and formal write request schema.
</objective>

<scope>
In scope:
- Extend `templates/final_round_summary.md` and the built-in template in `src/rsa_cli/templates.py` with YAML frontmatter and Chinese explanations.
- Add structured parsing and validation for `final_round_summary.md` in `src/rsa_cli/rounds.py` or a small helper module if that keeps the module clearer.
- Add `rsa round validate R001_xxx` and `rsa round complete-check R001_xxx` while preserving existing `rsa new-round`.
- Validate `README.md`, `final_round_summary.md`, declared `included_files`, optional `verification_review.md`, and `formal_write_requests`.
- Add tests that prove validation is read-only and produces actionable Chinese errors.

Out of scope:
- Do not create metadata records, apply literature map rows, download PDFs, perform web search, or write final academic prose.
- Do not require every optional template file to exist in a round.
- Do not introduce candidate IDs such as `C001`.
- Do not mutate round status as part of validation.
</scope>

<threat_model>
- T-03-01-01 False completion: a draft or partial round is treated as complete. Mitigate by requiring `README.md`, valid summary frontmatter, declared file existence, resolved candidate decisions, and human confirmation for `completed`.
- T-03-01-02 Optional-file overreach: validation forces irrelevant optional templates into every round. Mitigate with checklist mode where only files named in `included_files` are checked beyond the required pair.
- T-03-01-03 Candidate ambiguity: a candidate row lacks a decision or reason but still flows toward formal work. Mitigate by checking `verification_review.md` rows for `decision`, `reason`, and `last_checked` before allowing ready states.
- T-03-01-04 Schema drift: `formal_write_requests` becomes prose that later tools cannot parse. Mitigate by validating D-24 to D-27 as machine-readable YAML frontmatter.
- T-03-01-05 Language/key drift: translating field names breaks later tools, or English-only messages confuse the user. Mitigate by keeping keys and CLI flags English while explanations and errors are Chinese.
</threat_model>
