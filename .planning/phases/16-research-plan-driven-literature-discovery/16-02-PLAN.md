# Phase 16-02 Plan: Provider Search And Campaign Export

## Objective

<objective>
Add legal/auditable provider search and campaign export. Discovery results become campaign candidates with match evidence, dedup keys and Chinese rationale, while formal metadata remains untouched.
</objective>

## Must Haves

<must_haves>
<truth id="D-04">D-04: Default providers are legal/auditable scholarly or local configured providers; unauthorized mirrors and paywall bypass are rejected.</truth>
<truth id="D-05">D-05: Discovered papers feed existing campaign queues and do not create a separate queue or formal metadata.</truth>
<truth id="D-06">D-06: Provider failures, rate limits, empty results and ambiguous evidence must produce blocked/needs_review records, not fake candidates.</truth>
<truth id="D-08">D-08: Reserve provider plugin, iterative refinement, eval and Web UI hooks without implementing a broad platform.</truth>
</must_haves>

## Tasks

<tasks>
<task id="16-02-T1" type="auto">
<files>
- `src/rsa_cli/discovery.py`
- `tests/test_discovery.py`
</files>
<action>
Implement provider registry and deterministic provider search wrappers:
- at minimum support `openalex`, `crossref` and `offline`/query-only modes;
- use standard-library HTTP to avoid new core dependencies;
- normalize title/authors/year/doi/url/abstract/snippet/source provider;
- record provider status, errors, rate limit and Chinese repair hints.
</action>
<acceptance_criteria>
- Mocked provider responses normalize into candidate objects.
- Provider failures write blocked/partial status without fake success.
- Forbidden provider ids or unsupported providers fail closed.
</acceptance_criteria>
</task>

<task id="16-02-T2" type="auto">
<files>
- `src/rsa_cli/discovery.py`
- `tests/test_discovery.py`
</files>
<action>
Implement discovery result files:
- `DR###_results.yaml`;
- `DR###_report.md`;
- candidate ids, query links, source provider, dedup key, match evidence, status and Chinese rationale;
- future interfaces with `llm_query_generation`, `iterative_query_refinement`, `provider_plugins`, `discovery_eval`, `web_review_ui`.
</action>
<acceptance_criteria>
- Result YAML validates and links back to profile/query files.
- Markdown report is Chinese-first and states discovery is staging only.
- Future interface fields default to `not_run` or `not_enabled`.
</acceptance_criteria>
</task>

<task id="16-02-T3" type="auto">
<files>
- `src/rsa_cli/discovery.py`
- `src/rsa_cli/campaign.py`
- `tests/test_discovery.py`
- `tests/test_campaign.py`
</files>
<action>
Export discovered candidates into existing campaign records:
- create a campaign when requested;
- or append/import to an existing campaign;
- preserve source discovery ids and query ids;
- reuse campaign dedup/linking semantics;
- never write `metadata/P###.yaml` or `paper_index.md`.
</action>
<acceptance_criteria>
- Discovery candidates can create a campaign with queued/linked/duplicate states.
- Formal metadata files remain unchanged after export.
- Export is idempotent enough to avoid duplicate candidates on rerun through dedup keys.
</acceptance_criteria>
</task>
</tasks>
