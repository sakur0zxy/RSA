# Plan 07.1-02: Session-Aware Acquisition Integration And Verification

<objective>
Integrate browser session providers into Phase 7 source discovery and download so authorized cookie-based direct PDF URLs can be found, reviewed, downloaded, audited and reported through the existing candidate/source ledger flow.
</objective>

<must_haves>

- Cover D-11 by allowing `rsa source find P### --provider <browser_provider>` to generate candidates through a browser session provider.
- Cover D-12 by requiring an existing session, allowed target domain, non-`title_only` match basis, `result_type: pdf`, and complete authorization fields before auto-download.
- Cover D-13 by loading matching-domain cookies from Playwright storage state and sending them on HTTP download requests.
- Cover D-14 by failing closed when session state is missing, invalid, out-of-domain or lacks target-domain cookies.
- Cover D-15 by documenting that v1 only supports cookie-based direct PDF URLs and defers DOM automation.
- Cover D-18 through D-21 by preserving Phase 7 candidate record, source ledger, PDF acquisition report, hash, authorization/access mode, usage restriction, Chinese reason text, dedupe and formal-write boundaries.
- Cover D-19 by requiring every successful browser-session download to leave an auditable candidate record, source ledger entry, PDF acquisition report row, hash, authorization/access mode, usage restriction and Chinese reason.
- Cover D-20 by documenting and testing that session-downloaded PDFs are local authorized reading material only and cannot automatically write `literature_map.md`, `agent_research_notes.md`, metadata or thesis conclusions.
- Cover D-22 and D-23 by updating README/AGENTS/tests with Chinese-first explanations for browser session providers.

</must_haves>

<tasks>

1. Extend provider validation and candidate generation in `acquisition.py`.
   - For `provider_type: browser_session`, call browser session provider validation.
   - If session is missing, create a blocked candidate with Chinese reason instead of pretending the source is downloadable.
   - If session exists and query URL is allowed, mark direct PDF candidates eligible under existing Phase 7 rules.
   - Add `requires_browser_session`, `session_provider_id` and `session_state_path` fields to browser candidates.
2. Extend download flow.
   - Update `_download_to_tmp` to accept an optional browser session provider ID.
   - Load matching cookies from storage state for HTTP/HTTPS URLs.
   - Reject browser-session downloads with missing session, disallowed domain or missing cookie header.
   - Preserve `.tmp`, PDF validation, sha256, deduplication, source ledger behavior, PDF acquisition report rows, authorization/access fields, usage restriction and Chinese reason text.
3. Update CLI output and documentation.
   - Ensure `source find`, `source candidates`, `source download` show browser session candidates clearly.
   - Document example `.rsa/local.yaml` browser provider, login workflow, session status/clear, local-only storage and limitations.
   - Add AGENTS guidance that browser session providers are authorized local sessions, not credential automation, and that session-downloaded PDFs do not bypass formal write gates.
4. Add regression tests.
   - Browser provider without session produces blocked candidate.
   - Browser provider with fake storage state produces approved/downloadable candidate.
   - Download sends cookie header through a fake opener.
   - Disallowed domain and no matching cookie fail closed.
   - README/template tests confirm Chinese explanations.
5. Complete GSD closeout.
   - Write `07.1-01-SUMMARY.md` and `07.1-02-SUMMARY.md`.
   - Write `07.1-VERIFICATION.md`.
   - Update ROADMAP, REQUIREMENTS and STATE after all tests pass.

</tasks>

<threat_model>

- Risk: Browser session reuse could look like permission to download any reachable file.
  Mitigation: require provider allowlist, session file presence, cookie-domain match, authorization fields and candidate audit records.
- Risk: Cookies could be leaked through git or user-facing reports.
  Mitigation: never print cookie values, never write cookies outside `.rsa/sessions/`, and ignore session files in git.
- Risk: Later phases could treat session-downloaded PDFs as formal conclusions.
  Mitigation: preserve source-only status and formal write gates; reading/scoring/formal writes remain separate phases.
</threat_model>
