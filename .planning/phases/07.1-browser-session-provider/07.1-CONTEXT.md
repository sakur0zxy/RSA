# Phase 7.1: Browser Session Provider - Context

**Gathered:** 2026-05-14  
**Status:** Ready for planning  
**Mode:** `gsd-discuss-phase` inline, no subagents, agent-decided

<domain>

## Phase Boundary

Phase 7.1 是 Phase 7 Authorized Acquisition 的插入增强。它让用户可以在 RSA 管理的浏览器会话中手动登录学校图书馆、机构订阅、个人订阅或其他自定义资料库，然后 RSA 复用本地授权 browser session 检索和下载用户有权限访问的论文全文。

本阶段负责：

- 定义 `provider_type: browser_session` 的自定义 provider schema。
- 提供 `rsa source login <provider_id>`，打开 provider 登录页并保存本地 browser storage state。
- 提供 `rsa source session status|clear <provider_id>`，让用户监控和清除本地 session。
- 将 browser session provider 接入 Phase 7 的 source candidate、授权审查、自动下载、source ledger 和 report 流程。
- 保持中文优先的 CLI、模板、错误和文档。

本阶段不负责：

- 自动破解登录、保存账号密码或模拟用户凭据输入。
- 静默读取 Chrome/Edge/Firefox 等现有浏览器 cookies。
- 绕过 captcha、SSO、paywall、访问控制或数据库使用条款。
- 内置或自动化 Sci-Hub、LibGen、Z-Library 等未授权镜像。
- 自动阅读全文、阅读笔记、AI scoring、review UI 或 workflow orchestrator。
- 复杂 DOM 搜索、点击数据库页面或 JS 下载流；v1 只支持通过 cookie-based session 访问的直接 PDF URL。

</domain>

<decisions>

## Implementation Decisions

### Browser session provider schema

- **D-01:** 复用 `source_discovery.custom_providers`，新增 `provider_type: browser_session`，让用户继续在 `.rsa/local.yaml` 中添加本地私有资料库配置。
- **D-02:** `browser_session` provider 必须保留 Phase 7 基础字段：`provider_id`、`enabled`、`name_zh`、`provider_type`、`base_url`、`query_mode`、`query_template`、`allowed_domains`、`allowed_result_types`、`access_mode`、`requires_login`、`user_access_confirmed`、`authorization_policy`、`usage_restriction_zh`、`notes_zh`。
- **D-03:** `browser_session` provider 额外必须提供 `login_url`、`session_storage`、`session_required: true`，其中 `session_storage` 必须位于 `.rsa/sessions/` 下。
- **D-04:** `query_mode` v1 仍只支持 `url_template`，占位符为 `{doi}`、`{title}`、`{year}`、`{first_author}`、`{paper_id}`。
- **D-05:** provider 文本中出现 Sci-Hub、LibGen、Z-Library 或绕过访问控制语义时必须拒绝。

### Login and session capture

- **D-06:** `rsa source login <provider_id>` 打开 provider 的 `login_url`，用户在 RSA 控制的浏览器窗口里手动登录，RSA 在用户确认后保存 storage state。
- **D-07:** 默认浏览器实现使用可选 Playwright；未安装时给出中文错误，提示安装 `rsa-research-agent[browser]` 并运行 Playwright 浏览器安装。
- **D-08:** 登录流程不得保存密码、不得记录账号名、不得尝试自动填写登录表单、不得从现有浏览器配置中静默提取 cookies。
- **D-09:** session state 保存为 `.rsa/sessions/<provider_id>.storage_state.json`，旁路 metadata 保存为 `.rsa/sessions/<provider_id>.session.yaml`。
- **D-10:** `.rsa/sessions/**` 必须进入 `.gitignore`，session 文件不进入 git。

### Session reuse and download eligibility

- **D-11:** `rsa source find P### --provider <provider_id>` 可以使用 browser session provider 生成候选并走 Phase 7 的 monitored_auto 流程。
- **D-12:** browser session provider 的候选只有在 session 文件存在、目标域名命中 `allowed_domains`、匹配依据不是 `title_only`、`result_type` 是 `pdf`、授权字段完整时才允许自动下载。
- **D-13:** 下载时从 storage state 读取匹配目标域名的 cookies，并通过 HTTP `Cookie` header 访问直接 PDF URL。
- **D-14:** 如果 session 文件不存在、损坏、没有目标域名 cookie 或目标 URL 超出 allowed domains，必须 fail closed，并写入中文失败原因。
- **D-15:** v1 不做 DOM 搜索、按钮点击、验证码处理或复杂下载链接提取；这些可以在后续 browser automation phase 中扩展。

### CLI monitoring and lifecycle

- **D-16:** `rsa source session status <provider_id>` 是只读命令，显示 provider 名称、session 是否存在、session 文件路径、cookie 数量、origin 数量、更新时间和 allowed domains。
- **D-17:** `rsa source session clear <provider_id>` 只删除本地 session JSON 和 metadata，不修改 source ledger、候选记录、metadata 或 formal records。
- **D-18:** `rsa source status P###` 可以继续显示候选和下载状态；browser session 的 provider 级状态通过 `source session status` 查看。

### Audit and formal-record boundary

- **D-19:** browser session 下载成功后仍然必须写入 Phase 7 的 candidate record、source ledger、PDF acquisition report、hash、authorization/access mode、usage restriction 和中文原因。
- **D-20:** session 下载得到的 PDF 只是本地授权阅读材料，不能自动写入 `literature_map.md`、`agent_research_notes.md`、metadata 或论文正文。
- **D-21:** formal write gates 不变；任何正式记录更新仍必须通过对应命令和 `--human-confirmed`。

### Chinese-first user experience

- **D-22:** 所有 CLI help、成功提示、错误、模板字段说明、README、AGENTS 和 GSD 文档必须中文优先。
- **D-23:** 英文字段名、YAML key、CLI flag、status enum 和代码标识保持英文稳定，但用户需要填写或阅读的位置必须提供中文解释。

### Agent Discretion

- 实现可以决定内部 helper 名称、dataclass 字段、可选 Playwright wrapper 的拆分方式和测试 fake runner 的接口。
- README 示例 provider 可以使用 `example.edu` 等占位域名，不写入真实学校地址。
- v1 可以只支持 cookie-based HTTP 下载；复杂浏览器页面交互作为后续 deferred idea 记录。

</decisions>

<specifics>

## Specific Ideas

- 用户希望系统重要特征是“能够在用户不干预的情况下自动进行，用户可以监控重要环节，并进行调整”。
- 用户明确希望可以打开自定义资料库登录界面，登录后让系统保存下载所需 cookies 或等价 session 信息。
- 用户希望自定义资料库来源有明确模板。
- 用户要求项目主要面向中文用户：用户可见内容中文为主，变量、字段、参数名可以保持英文。

</specifics>

<code_context>

## Existing Code Insights

### Reusable Assets

- `ProjectConfig.custom_source_providers` 已能读取 `.rsa/local.yaml` 中的本地 provider 配置。
- `validate_custom_providers` 已有 Phase 7 provider schema、forbidden source 检查和中文错误模式。
- `_custom_provider_candidates` 已能从 provider `query_template` 生成 candidate。
- `download_candidate` 已能复用 candidate 状态、`.tmp` 下载、PDF 校验、sha256 去重、source ledger 和 report 写入。
- CLI 已有 `rsa source find|candidates|download|status`，适合扩展 `login` 和 `session`。

### Established Patterns

- 用户可见输出中文优先。
- YAML 写入使用 `yaml.safe_dump(..., allow_unicode=True, sort_keys=False)`。
- `status`、`validate`、`candidates` 类命令只读。
- PDF 与 session 等本地二进制/私密材料不进入 git；文本 manifest/ledger 可审计。
- expected errors 必须无 traceback。

### Integration Points

- 新增 `src/rsa_cli/browser_session.py` 管理 session provider、session path、Playwright login wrapper、status、clear 和 cookie header。
- `src/rsa_cli/acquisition.py` 需要识别 `provider_type: browser_session`，并在下载阶段注入 session cookies。
- `src/rsa_cli/cli.py` 需要新增 `source login` 与 `source session status|clear`。
- `templates/browser_session_provider.yaml` 和 `TEMPLATE_FILES` 需要提供中文字段说明。
- `.gitignore` 需要忽略 `.rsa/sessions/**`。

</code_context>
