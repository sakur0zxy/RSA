# Phase 7.1 Browser Session Provider - Discussion WIP

**Started:** 2026-05-14  
**Mode:** no subagents; agent decides; Chinese-first user-facing content  
**Purpose:** 临时记录每个小点的讨论决策，完成后整理进 `07.1-CONTEXT.md`。

## 逐点讨论记录

### 1. Phase boundary / 阶段边界

- 决策：Phase 7.1 只补强 Phase 7 的授权来源获取能力，允许用户打开自定义资料库登录页并手动登录，然后 RSA 复用该本地授权浏览器 session 进行检索/下载。
- 不做：自动破解登录、保存账号密码、静默读取现有浏览器 cookies、绕过 captcha/SSO/paywall、自动化 Sci-Hub 或未授权镜像。
- 理由：用户需要“自动进行 + 可监控调整”，但 v1/v2 的 formal guardrails 和授权边界不能被削弱。

### 2. Provider schema / 用户自定义资料库模板

- 决策：继续复用 `source_discovery.custom_providers`，新增 `provider_type: browser_session`。
- 必填字段：沿用 Phase 7 provider 基础字段，并额外要求 `login_url`、`session_storage`、`session_required: true`。
- 推荐存放：`.rsa/local.yaml`，避免把学校数据库入口、个人订阅路径或内部资料库地址提交到 git。
- `session_storage` 必须指向 `.rsa/sessions/` 下的本地文件；不接受绝对路径或跳出项目的路径。

### 3. Login capture / 登录捕获方式

- 决策：提供 `rsa source login <provider_id>`。
- 行为：RSA 打开由 provider 定义的 `login_url`，用户在受控浏览器窗口中自行登录；登录完成后 RSA 保存 browser storage state。
- 默认实现：使用可选 Playwright 依赖；未安装时给出中文错误和安装提示。
- 测试实现：核心逻辑允许注入 fake runner，不需要真实浏览器即可测试 schema、状态和文件行为。

### 4. Session storage / 本地 session 文件

- 决策：session 文件保存到 `.rsa/sessions/<provider_id>.storage_state.json`，并写入旁路 metadata `.rsa/sessions/<provider_id>.session.yaml`。
- session 文件 local-only，`.gitignore` 必须忽略 `.rsa/sessions/**`。
- 记录 metadata：`provider_id`、`login_url`、`allowed_domains`、`session_file`、`created_at`、`updated_at`、中文限制说明。
- 不记录：用户名、密码、学校账号、token 明文解释或任何需要提交到正式记录的敏感内容。

### 5. Session reuse / 复用 session 检索与下载

- 决策：`rsa source find P### --provider <browser_provider>` 复用 Phase 7 candidate 流程生成候选。
- 对 `browser_session` provider，只有 session 存在且目标 URL 域名在 `allowed_domains` 内，才允许进入自动下载审查。
- 下载时从 Playwright storage state 中提取匹配域名 cookie，通过 HTTP `Cookie` header 访问用户已有权限的 PDF URL。
- v1 限制：自动下载只支持 cookie-based session 访问的直接 PDF URL；需要 JS 页面点击、DOM 解析或复杂数据库 API 的搜索留给后续 phase。

### 6. Query rules / 搜索依据

- 决策：继续使用 Phase 7 的 `query_mode: url_template`，占位符仍为 `{doi}`、`{title}`、`{year}`、`{first_author}`、`{paper_id}`。
- 检索优先级继承 Phase 7：`doi` > `official_url` > `arxiv_id` > `title_year_first_author` > `title_only`。
- `title_only` 不得自动下载；即使存在 browser session，也只能进入候选/审查状态。

### 7. CLI monitoring / 监控和调整入口

- 决策：新增只读/本地管理命令：
  - `rsa source session status <provider_id>`
  - `rsa source session clear <provider_id>`
- `status` 显示是否存在 session、session 文件路径、cookie 数量、origin 数量、更新时间和 allowed domains。
- `clear` 删除本地 session JSON 和 metadata，不修改 formal records、source ledger 或候选记录。

### 8. Fail-closed guardrails / 失败边界

- 决策：以下情况必须中文报错并 fail closed：
  - provider 缺少 `login_url`、`session_storage` 或 `allowed_domains`。
  - `session_storage` 不在 `.rsa/sessions/` 下。
  - 目标 URL 域名不在 `allowed_domains`。
  - session 文件不存在、损坏或没有目标域名 cookie。
  - provider 文本包含 Sci-Hub、LibGen、Z-Library 等绕过访问控制来源。
- 下载失败只能写入 candidate/report 的 failed 状态，不能伪造 source ledger 成功记录。

### 9. Chinese-first / 中文优先

- 决策：CLI help、错误、状态输出、模板字段说明、README 和 GSD 文档都必须中文优先。
- 英文字段名保留稳定，例如 `provider_id`、`browser_session`、`login_url`、`session_storage`、`allowed_domains`、`session_required`。
- 所有需要用户填写的英文 key 都要有中文解释。
