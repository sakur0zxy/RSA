# Plan 07.1-01: Browser Session Provider Schema And Session CLI

<objective>
Create the browser session provider foundation: explicit local provider schema, local-only session state paths, Chinese-first login/status/clear commands, and tests that do not require a real browser.
</objective>

<must_haves>

- Cover D-01 by using `source_discovery.custom_providers` with `provider_type: browser_session` instead of creating a separate hidden config surface.
- Cover D-02 and D-03 by validating browser session provider fields including `login_url`, `session_storage` and `session_required: true`.
- Cover D-04 by preserving `query_mode: url_template` and the existing `{doi}` / `{title}` / `{year}` / `{first_author}` / `{paper_id}` placeholders.
- Cover D-05 by rejecting Sci-Hub, LibGen, Z-Library and other bypass-source patterns in provider config.
- Cover D-06 through D-09 by implementing `rsa source login <provider_id>` with optional Playwright storage-state capture, local metadata, no password storage, no username recording, no auto-filled login forms, no silent extraction from existing browsers, and a Chinese error/install hint when optional Playwright support is missing, including `rsa-research-agent[browser]` and running the Playwright browser installation command.
- Cover D-07 exactly: 默认浏览器实现使用可选 Playwright；未安装时给出中文错误，提示安装 `rsa-research-agent[browser]` 并运行 Playwright 浏览器安装。
- Cover D-10 by ignoring `.rsa/sessions/**` in git.
- Cover D-16 and D-17 by adding `rsa source session status <provider_id>` and `rsa source session clear <provider_id>`.
- Cover D-22 and D-23 by ensuring all CLI help, success messages, errors, templates and test assertions are Chinese-first while English keys remain stable.

</must_haves>

<tasks>

1. Add `src/rsa_cli/browser_session.py`.
   - Define `BrowserSessionError`, `BrowserSessionStatus`, `BrowserSessionLoginResult`.
   - Resolve `.rsa/sessions/` paths safely and reject absolute or escaping `session_storage` paths.
   - Find and validate `provider_type: browser_session` providers by `provider_id`.
   - Provide `login_browser_session`, `browser_session_status`, `clear_browser_session` and cookie/storage-state helpers.
   - Use an injectable login runner for tests; default runner imports Playwright only when login is executed and raises a Chinese error mentioning `rsa-research-agent[browser]` when unavailable.
   - Enforce D-08 directly: never store passwords, never record account names, never auto-fill login forms, and never read existing browser cookies silently.
2. Extend config helpers.
   - Add `ProjectConfig.sessions_root`.
   - Keep `.rsa/local.yaml` override behavior unchanged.
   - Validate that `.rsa/sessions/` remains local-only through tests and `.gitignore`.
3. Extend CLI.
   - Add `rsa source login <provider_id> [--headless] [--wait-seconds N]`.
   - Add `rsa source session status <provider_id>`.
   - Add `rsa source session clear <provider_id>`.
   - Expected errors must return non-zero with Chinese text and no traceback.
4. Add template support.
   - Add `templates/browser_session_provider.yaml`.
   - Add fallback content to `TEMPLATE_FILES`.
   - Update skeleton/template tests so new projects receive the Chinese provider template.
5. Add tests.
   - Provider schema success and failure.
   - Session path cannot escape `.rsa/sessions/`.
   - Fake login runner writes storage state and metadata.
   - Status is read-only and clear deletes only session files.
   - CLI help lists login/session commands.

</tasks>

<threat_model>

- Risk: Session files could be accidentally committed.
  Mitigation: `.gitignore` covers `.rsa/sessions/**`; tests assert this boundary.
- Risk: A provider could point session storage outside the project.
  Mitigation: path resolver rejects absolute paths and `..` escapes.
- Risk: Login command could be mistaken for credential automation.
  Mitigation: CLI/help/docs state that the user logs in manually and RSA does not save passwords or silently extract existing cookies.
</threat_model>
