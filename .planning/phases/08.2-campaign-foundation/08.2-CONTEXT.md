# Phase 08.2: Campaign Foundation - Context

**Gathered:** 2026-05-19  
**Status:** Complete; context refreshed after retrospective `gsd-discuss-phase 8.2`

<domain>

## Phase Boundary

Phase 8.2 是在 Phase 8.1 之后临时插入的轻量阶段，用来提前实现 Phase 11 中不依赖 Phase 9 AI scoring、不依赖 Phase 10 Workflow Orchestrator、也不依赖 UI 的简单 Campaign Foundation。

本阶段只交付批量候选队列的基础能力：创建 campaign、导入 CSV/TSV/YAML 候选、轻量去重、链接已存在的正式 metadata，以及只读校验/状态汇总。它不负责论文获取、自动阅读、AI 评分、批量自动运行、review workspace 或 formal write。

</domain>

<decisions>

## Implementation Decisions

### Phase Role

- **D-01:** Phase 8.2 保留为插入阶段，定位是 “Campaign Foundation”，不是完整 Phase 11。
- **D-02:** Phase 8.2 可以提前完成，因为它只依赖本地 Markdown/YAML、metadata 和现有 CLI 模式，不依赖 Phase 9/10 的评分或编排结果。
- **D-03:** Phase 8.2 的实现结果可以被 Phase 9、Phase 10 和 Phase 11 后续消费，但不能反向扩大 Phase 8.2 的职责。

### Campaign Data Contract

- **D-04:** Campaign 文件使用 `01_literature/campaigns/C###.yaml`，保持本地可审计、可 diff、可回滚。
- **D-05:** 导入格式支持 CSV、TSV 和 YAML，字段名保持英文稳定；用户可见说明、错误和 README 内容使用中文优先。
- **D-06:** 缺少标题和 DOI 的候选不得静默进入正常队列，必须标记为 `blocked` 或产生中文校验错误，避免制造伪候选。

### Dedup And Linking Semantics

- **D-07:** 轻量去重按 DOI、URL 或 `title/year/first_author` 生成 `dedup_key`；重复项不删除，只标记 `duplicate` 并保留来源行。
- **D-08:** `linked` 只表示候选与现有 `metadata/P###.yaml` 匹配，不表示论文已经完成阅读、评分、人工批准或正式学术结论。
- **D-09:** Phase 8.2 不创建新的正式 `paper_id`，也不把 campaign 候选直接写入 `literature_map.md`、`agent_research_notes.md` 或任何 formal record。

### Automation Boundary

- **D-10:** Phase 8.2 可以自动完成候选导入、去重、状态汇总和 metadata 链接检查。
- **D-11:** Phase 8.2 不自动触发下载、阅读、视觉证据提取、AI scoring 或 workflow orchestration。
- **D-12:** 后续自动化应由 Phase 10/11 接入 campaign 队列，并继续遵守 formal write gate。

### Chinese-First User Experience

- **D-13:** CLI help、成功提示、错误信息、README、GSD 文档和用户需要阅读的说明必须中文优先。
- **D-14:** `campaign_id`、`item_id`、`dedup_key`、`status`、YAML key、CLI flag 等机器可读标识保持英文稳定，但在用户可读位置提供中文解释。

### Retrospective GSD Compliance

- **D-15:** Phase 8.2 初次执行属于 GSD-compatible fallback：已补齐 CONTEXT、PLAN、SUMMARY、VERIFICATION、ROADMAP、STATE、REQUIREMENTS 和提交记录，但不是严格的逐项交互式 discuss。
- **D-16:** 本次 `gsd-discuss-phase 8.2` 复盘的目标是补齐决策语义和审计记录，不重新执行实现，也不要求重新规划 Phase 8.2。

### the agent's Discretion

- 具体 YAML 字段顺序、内部 dataclass 名称、helper 函数拆分、测试 fixture 组织方式由实现保持与现有 `rsa_cli` 风格一致。
- 后续 Phase 9/10/11 可在不破坏当前 campaign 文件兼容性的前提下追加字段，例如 scoring summary、workflow run id、review queue metadata。

</decisions>

<code_context>

## Existing Code Insights

### Reusable Assets

- `ProjectConfig` already centralizes project paths; Phase 8.2 adds `campaigns_root` instead of scattering path literals.
- Existing CLI command style uses `argparse` subcommands and Chinese-first print/error text; campaign commands follow that pattern.
- Existing YAML helpers and metadata loading patterns make local campaign YAML compatible with the broader Markdown/YAML harness.

### Established Patterns

- Formal records remain higher authority than generated artifacts.
- Local-only binary or downloaded assets stay outside git; auditable YAML/Markdown records stay text-based.
- Read-only commands such as `validate` and `status` report problems without mutating campaign files.
- Fail-closed behavior is preferred when input identity is insufficient or unsafe to treat as a normal queue item.

### Integration Points

- Phase 9 can consume campaign items as scoring candidates, but AI scoring must remain review guidance only.
- Phase 10 can orchestrate acquisition/reading/scoring over campaign items, but must stop before formal writes.
- Phase 11 can add ranking, filtering, queue review and batch workflow state on top of Phase 8.2 queues.
- Phase 12 can display campaign queues and linked records in the local review workspace.

</code_context>

<specifics>

## Specific Ideas

- 用户明确希望先做“不需要依赖的简单部分”，因此 Phase 8.2 被拆成只依赖本地文件和现有 CLI 的基础队列能力。
- 用户强调项目主要面向中文用户，因此所有用户可见内容继续以中文为主，英文仅用于稳定字段名、参数名和代码标识。
- Phase 8.2 的完成不改变 Phase 11 的存在意义；Phase 11 仍负责完整 Campaign & Batch Review。

</specifics>

<deferred>

## Deferred Ideas

- Campaign ranking/filtering based on relevance、quality、read priority remains Phase 9/11.
- Batch automatic execution over campaign queues remains Phase 10/11.
- Review workspace UI remains Phase 12.
- Formal write from campaign items remains out of Phase 8.2 and must go through existing formal gate.
- Deep scholarly metadata integrations remain deferred unless later phases prove they are necessary.

</deferred>
