# Plan 07-02: Authorized Download Engine And Source Ledger Integration

<objective>
Implement the monitored automatic download path for approved candidates, including fail-closed authorization checks, temporary-file writes, hash deduplication, source ledger updates, primary-version selection and Chinese acquisition reporting.
</objective>

<must_haves>

- Cover D-11 by downloading only candidates approved through DOI, arXiv ID, explicit official PDF URL, or title+year+first_author matches from allowed providers.
- Cover D-12 by using medium authorization judgment: direct-access PDFs, user-authorized school account access, institutional subscriptions and personal subscriptions may be downloaded when their access basis is recorded.
- Cover D-13 by treating "reachable" as insufficient and recording `authorization_mode`, `access_mode`, `authorization_basis_zh`, `usage_restriction_zh` or `license_note` after download.
- Cover D-14 by supporting `open_access`, `direct_access`, `user_authorized_access`, `institutional_subscription`, `personal_subscription`, `provided`, `local`, `unknown` and `blocked`.
- Cover D-15 by allowing already-authorized school, institutional or personal subscription links/files/providers while never saving passwords, simulating login, bypassing captcha/SSO/paywall or breaking access controls.
- Cover D-16 by allowing non-OA or pending-authorization material to enter draft/pending reading flows only, never formal `literature_map.md`, `agent_research_notes.md`, `metadata` or thesis conclusions automatically.
- Cover decisions D-18 through D-21 by supporting automatic download from `find`-approved candidates plus explicit manual candidate or URL download paths.
- Cover D-22 by saving PDFs under `01_literature/pdfs/P###/S###_<provider_id>_<version_label>.pdf`.
- Cover D-23 by preserving multiple PDF versions for the same paper while selecting one primary version automatically.
- Cover D-24 by using primary priority `publisher_version`, `accepted_manuscript`, `institutional_subscription`, `repository_copy`, `arxiv_preprint`, `preprint`, `unknown`.
- Cover D-25 by recording `is_primary`, `version_label` and `primary_reason_zh`, while allowing later user adjustment without deleting PDFs.
- Cover D-26 by deduplicating by `sha256`, creating no new PDF for identical content, never overwriting existing files, and recording `duplicate_of` plus Chinese reason text.
- Cover D-27 by saving hash-different files as new versions with new `source_id` even when DOI/title match.
- Cover D-28 by writing `.tmp` first, verifying type/hash/deduplication, then atomically landing the file and cleaning failed temporary files.
- Cover D-29 and D-30 by returning Chinese errors, status reasons and report rows with stable English field names.

</must_haves>

<tasks>

1. Extend source authorization and access enums without breaking Phase 6 records.
   - Support `open_access`, `direct_access`, `user_authorized_access`, `institutional_subscription`, `personal_subscription`, `provided`, `local`, `unknown`, `blocked`.
   - Keep existing `provided`, `local`, `authorized`, `open_access`, `user_authorized` compatibility where already used.
2. Add download helpers in `acquisition.py`.
   - `download_best_candidate(config, paper_id)`;
   - `download_candidate(config, paper_id, candidate_id)`;
   - `download_direct_url(config, paper_id, url, authorization_mode, access_mode, usage_restriction_zh, ...)`.
3. Implement fail-closed download authorization.
   - Refuse `title_only` candidates.
   - Refuse `unknown` or `blocked` authorization.
   - Refuse subscription-style sources without `user_access_confirmed: true` or an explicit authorization basis.
   - Refuse direct URL downloads missing authorization mode, access mode or Chinese usage restriction.
4. Implement safe file handling.
   - Download to a `.tmp` file inside the target paper PDF directory.
   - Verify non-empty content and PDF-like file type for `result_type: pdf`.
   - Compute `sha256`.
   - Delete `.tmp` on failure.
   - Atomically move to `01_literature/pdfs/P###/S###_<provider_id>_<version_label>.pdf`.
5. Integrate with `sources/P###.yaml`.
   - Add a source ledger entry for every successful unique download.
   - Store `source_id`, `source_type`, `authorization`, `authorization_mode`, `access_mode`, `authorization_basis_zh`, `usage_restriction_zh`, `source_url`, `local_path`, `sha256`, `version_label`, `is_primary`, `primary_reason_zh`, `status`, `added_at`.
   - Preserve older Phase 6 source records as valid.
6. Implement deduplication and multi-version handling.
   - If `sha256` already exists for the same paper, do not create another PDF.
   - Mark the candidate as `duplicate`, set `duplicate_of`, and write a Chinese reason.
   - If hash differs, save as a new version and choose primary by priority: `publisher_version`, `accepted_manuscript`, `institutional_subscription`, `repository_copy`, `arxiv_preprint`, `preprint`, `unknown`.
7. Update acquisition report behavior.
   - Write `available`, `blocked`, `failed`, `duplicate`, or `partial_failed` rows to `pdf_acquisition_report.md`.
   - Include Chinese notes explaining why a source was downloaded, skipped, blocked or deduplicated.
8. Add tests for:
   - approved open-access candidate download;
   - institutional subscription candidate requiring user authorization confirmation;
   - blocked/unknown candidate refusal;
   - direct URL download requiring explicit authorization fields;
   - duplicate hash detection without overwrite;
   - multi-version primary selection;
   - failed download cleanup of `.tmp`;
   - source ledger validation for extended fields.

</tasks>

<threat_model>

- Risk: Automatic download could silently save unauthorized or uncertain material.
  Mitigation: Centralize authorization checks and mark uncertain sources blocked before file transfer.
- Risk: Partial or malicious files could be recorded as PDFs.
  Mitigation: Verify file type and non-empty content before ledger writes, then clean temporary files on failure.
- Risk: Repeated downloads could overwrite a legally obtained local copy.
  Mitigation: Use source IDs, hash deduplication and atomic file names; never overwrite existing PDF versions.
</threat_model>
