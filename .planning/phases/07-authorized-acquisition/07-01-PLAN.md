# Plan 07-01: Source Candidate Model And Provider Configuration

<objective>
Create the Phase 7 source discovery foundation: local candidate records, trusted/custom provider configuration, deterministic match review, and Chinese-first schema guidance.
</objective>

<must_haves>

- Cover D-01 by implementing conservative built-in source discovery from DOI, official URL, arXiv/preprint, OA metadata, institutional repositories, author pages and lab publication pages.
- Cover D-02 by supporting user-defined search sources, database sources, school database entries, institutional repositories and lab publication pages.
- Cover D-03 by requiring custom providers to use a fixed YAML template, preferably in local `.rsa/local.yaml`, so private school or database URLs are not committed.
- Cover D-04 by ensuring custom providers only expand discovery and never reduce match review, authorization recording or download-boundary checks.
- Cover D-05 by validating every `source_discovery.custom_providers` item for `provider_id`, `enabled`, `name_zh`, `provider_type`, `base_url`, `query_mode`, `query_template`, `allowed_domains`, `allowed_result_types`, `access_mode`, `requires_login`, `user_access_confirmed`, `authorization_policy`, `usage_restriction_zh` and `notes_zh`.
- Cover D-06 by initially supporting `query_mode: url_template` with `{doi}`, `{title}`, `{year}`, `{first_author}` and `{paper_id}` placeholders.
- Cover D-07 by allowing `access_mode: institutional_subscription` and `personal_subscription` while never storing passwords or automatically handling login flows.
- Cover D-08 by using fixed lookup priority: `doi`, `official_url`, `arxiv_id`, `title_year_first_author`, `title_only`.
- Cover D-09 by allowing `title_only` to create candidates but never trigger automatic download alone.
- Cover D-10 by recording candidate match evidence such as `doi_match`, `title_match_score`, `year_match`, `author_match` and `source_domain_allowed`.
- Cover D-11 by allowing automatic download eligibility only for DOI, arXiv ID, explicit PDF official URL, or title+year+first_author matches from allowed providers.
- Cover D-17 by explicitly rejecting Sci-Hub, unauthorized mirrors, credential bypass sources and domains intended to circumvent access control.
- Cover D-18 through D-21 at the planning boundary by separating candidate discovery from download while marking which candidates are approved for monitored auto-download.
- Cover D-29 and D-30 by making every user-facing schema comment, validation error and status reason Chinese-first while keeping YAML keys, CLI flags and enum values stable English.

</must_haves>

<tasks>

1. Add `source_candidates_root` and `source_discovery` accessors to `ProjectConfig`.
   - Default `source_discovery.automation_mode` to `monitored_auto`.
   - Default `source_discovery.default_auto_download` to `true`.
   - Load `source_discovery.custom_providers` from merged `rsa.yaml` and `.rsa/local.yaml`.
2. Extend skeleton initialization to create `01_literature/source_candidates/` and install `templates/source_candidates.yaml`.
3. Add `src/rsa_cli/acquisition.py` with candidate data helpers:
   - `candidate_record_path(config, paper_id)`;
   - `load_candidate_record`;
   - `write_candidate_record`;
   - sequential `candidate_id` allocation using `SC###`;
   - formal metadata validation using existing `metadata/P###.yaml` rules.
4. Implement provider schema validation for `source_discovery.custom_providers`.
   - Required keys: `provider_id`, `enabled`, `name_zh`, `provider_type`, `base_url`, `query_mode`, `query_template`, `allowed_domains`, `allowed_result_types`, `access_mode`, `requires_login`, `user_access_confirmed`, `authorization_policy`, `usage_restriction_zh`, `notes_zh`.
   - Initially support `query_mode: url_template` with `{doi}`, `{title}`, `{year}`, `{first_author}`, `{paper_id}` placeholders.
   - Fail with Chinese errors when a provider is missing required fields, has no allowed domain, or references a forbidden bypass domain.
5. Implement deterministic candidate generation from formal metadata.
   - Use lookup priority `doi`, `official_url`, `arxiv_id`, `title_year_first_author`, `title_only`.
   - Record `match_basis`, `match_evidence`, `authorization_mode`, `access_mode`, `authorization_basis_zh`, `usage_restriction_zh`, `status`, `reason_zh`, `created_at`.
   - Mark DOI, `official_url`, arXiv and `title_year_first_author` matches from allowed providers as `approved_for_download` when authorization rules pass.
   - Keep `title_only` matches as `candidate` or `blocked`; never allow `title_only` alone to trigger automatic download.
6. Add source candidate validation that is read-only.
   - Validate candidate IDs, provider IDs, status enums, authorization/access mode enums, match evidence, Chinese reason fields and local path/hash references when present.
   - Validate that every downloaded candidate points to a source ledger entry when `downloaded_source_id` is set.
7. Add focused tests for:
   - default source discovery config;
   - custom provider schema success and failure;
   - forbidden bypass source rejection;
   - DOI and official URL candidate creation;
   - title-only candidate not being approved for automatic download;
   - read-only validation;
   - Chinese explanations in templates and errors.

</tasks>

<threat_model>

- Risk: Custom providers could be used to hide unauthorized mirrors or bypass access control.
  Mitigation: Validate provider domains and policy fields, reject known bypass patterns, require `user_access_confirmed` and Chinese usage restrictions for subscription-style access.
- Risk: Matching by title only could download the wrong paper.
  Mitigation: Treat `title_only` as review-only and require DOI, official URL, arXiv ID, or title+year+first_author evidence before automatic download eligibility.
- Risk: Private school database URLs could be committed.
  Mitigation: Document `.rsa/local.yaml` as the preferred location for custom providers and keep templates generic.
</threat_model>
