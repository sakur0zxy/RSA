# Plan 07-03: CLI Workflow, Documentation And Regression Coverage

<objective>
Expose Phase 7 as a Chinese-first monitored automation workflow through `rsa source find|candidates|download`, document custom providers and safety boundaries, then verify the full harness.
</objective>

<must_haves>

- Cover D-18 by keeping `find` and `download` as separate concepts while making `monitored_auto` the default mode.
- Cover D-19 by making `rsa source find P001` search, review and download rule-approved sources by default, then write candidates, source ledger, local PDF path and acquisition report.
- Cover D-20 by retaining monitoring/debug commands: `--no-download`, `rsa source candidates P001`, `rsa source download P001 --best` and `rsa source download P001 --candidate SC001`.
- Cover D-21 by allowing direct URL download only when manual commands explicitly declare authorization and usage restrictions, while automatic URLs must come from built-in providers, custom providers or task queues with candidate/review/download records.
- Cover D-29 by keeping CLI help, success output, errors, reports, templates and docs Chinese-first.
- Cover D-30 by retaining English YAML keys, CLI flags, table columns and status enums while adding Chinese explanations wherever users read or fill them.
- Preserve the project convention that automatic acquisition may create candidates and source ledgers, but does not write formal academic conclusions or bypass formal write gates.
- Ensure every CLI help string, success message, expected error, report note and README section is understandable to Chinese users while retaining stable English command names and schema keys.

</must_haves>

<tasks>

1. Extend `rsa source` CLI with Phase 7 commands.
   - `rsa source find P001 [--no-download] [--provider PROVIDER_ID] [--max-results N]`.
   - `rsa source candidates P001`.
   - `rsa source download P001 --best`.
   - `rsa source download P001 --candidate SC001`.
   - `rsa source download P001 --url URL --authorization-mode MODE --access-mode MODE --usage-restriction-zh TEXT [--provider-id manual_url] [--version-label publisher_version]`.
2. Make `rsa source find P001` default to monitored automation.
   - Generate or refresh candidates.
   - Auto-review candidates using deterministic rules.
   - Auto-download approved candidates unless `--no-download` is provided.
   - Print a concise Chinese summary: candidates found, approved, downloaded, duplicate, blocked, failed, and where to inspect records.
3. Add monitoring and adjustment commands.
   - `rsa source candidates P001` prints candidate status, match basis, authorization mode, access mode, reason and local path if present.
   - `rsa source status P001` includes candidate count and download states in addition to Phase 6 ledger totals.
   - `rsa source download` lets users manually retry or choose a specific candidate without changing formal metadata.
4. Update documentation.
   - Add README sections for Phase 7 workflow, custom provider YAML template, default automation, monitoring controls, authorization boundary and local-only PDF policy.
   - Add AGENTS guidance for Phase 7 commands and the no-Sci-Hub/no-bypass boundary.
   - Ensure examples are Chinese-first and explain English YAML keys/CLI flags where users must fill them.
5. Add CLI and template regression tests.
   - Help surface includes `find`, `candidates`, `download`, `--no-download`, `--best`, `--candidate`, `--authorization-mode`, `--usage-restriction-zh`.
   - `find --no-download` creates candidates but no PDF.
   - default `find` downloads only approved candidates.
   - manual direct URL download without required authorization fields fails without traceback.
   - status/candidates commands are read-only.
   - README/template tests confirm Chinese user-facing explanation exists.
6. Finalize Phase 7 planning/execution docs during execute phase.
   - Generate `07-01-SUMMARY.md`, `07-02-SUMMARY.md`, `07-03-SUMMARY.md` after implementation.
   - Generate `07-VERIFICATION.md` after full verification.
   - Update ROADMAP and STATE only after tests pass.

</tasks>

<threat_model>

- Risk: Users may interpret automatic acquisition as permission to download anything reachable.
  Mitigation: CLI help, README and expected errors state that automatic download is limited to open, direct, provided, local or user-authorized access and never bypasses access control.
- Risk: A single command could hide important failures.
  Mitigation: Print Chinese summaries and write machine-readable candidate/source/report records for every downloaded, blocked, duplicate or failed item.
- Risk: Later phases could treat downloaded non-OA PDFs as formal conclusions.
  Mitigation: Documentation and CLI output state that acquisition creates source material only; reading drafts, scoring and formal writes remain gated in later phases.
</threat_model>
