## Overview

v1.0 shipped a local-first Python/Markdown/YAML research agent harness for auditable literature workflows. It establishes topic profiles, bounded research rounds, formal metadata gates, candidate staging, literature maps, gap reports, authorized reading notes, formal write guardrails, trace summaries and deterministic eval fixtures.

No dedicated `.planning/v1.0-MILESTONE-AUDIT.md` existed at close. Closure used phase verification documents plus full automated tests as evidence; a future `$gsd-audit-milestone` style pass can be added before v2 release if desired.

## Milestone Summary

### Key Accomplishments

- Built a reusable local CLI harness around `rsa init`, `validate-profile`, `new-round`, `round`, `map`, `gap`, `note`, `formal` and `eval`.
- Established metadata-first formal records with paper IDs, index consistency and human-confirmed writes.
- Added candidate staging and verification review so unverified findings stay out of formal records.
- Added literature mapping and gap reporting to connect papers to topic questions and writing plans.
- Added authorized reading notes and blocked unauthorized/missing source behavior.
- Added deterministic eval fixtures and trace summaries for regression visibility.

### Key Decisions

- Local Markdown/YAML remains the v1 storage layer for human review and git diff.
- Formal records outrank agent outputs.
- `validate` commands are read-only; `generate`/`propose` commands can write generated artifacts but not formal records.
- Formal writes require explicit human confirmation and conflict-free validation.
- User-facing text must include Chinese explanations while stable schema names remain English.
- Eval fixtures must be local and deterministic, not network or LLM judged.

### Issues Deferred

- Citation manager sync.
- Scholarly API integrations.
- Local Web UI.
- Large-scale batch literature processing.
- Claim-level citation checking for synthesis drafts.
- LLM-judged semantic evals.
- Full multi-agent orchestration.

### Technical Debt

- Some older planning files contain encoding artifacts from earlier sessions; new README and archive docs are clean UTF-8.
- Markdown table parsers are appropriate for v1 but should be revisited if formal records become complex.
- Trace extraction currently supports known round artifacts only.
